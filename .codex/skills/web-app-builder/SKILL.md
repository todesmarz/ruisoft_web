# Web App Builder スキル

ユーザーが作りたいWebアプリを**仕様合意 → 実装 → 再生成プロンプト出力**の流れで構築するスキル。

対象：GitHub Pages公開を前提とした静的Webアプリ（HTML/CSS/JS 単一ファイル）

---

## 🔄 全体フロー

```
Phase 1: ヒアリング（アイデア把握）
    ↓
Phase 2: 仕様書（叩き台）提示
    ↓
Phase 3: 仕様レビュー・修正（合意まで繰り返す）
    ↓
Phase 4: 実装
    ↓
Phase 5: 再生成プロンプト出力
```

---

## Phase 1: ヒアリング

ユーザーのアイデアから以下を把握する。不明な点は質問する（一度に複数質問してよい）。

- **目的**：何のために作るか、誰が使うか
- **主な機能**：何ができるか（箇条書きレベルでOK）
- **データの扱い**：ローカルストレージ使用か、データ永続化が必要か
- **デザインイメージ**：雰囲気・参考サイト・カラーイメージ（なければ省略可）

把握できたら、**Phase 2へ進む前に「仕様書を作ります」と一言添えて**から提示する。

---

## Phase 2: 仕様書（叩き台）提示

以下のフォーマットで仕様書をMarkdown形式で出力する。

```markdown
# 仕様書：{アプリ名}

## 1. 概要
- 目的：
- 対象ユーザー：
- 公開方法：GitHub Pages（静的サイト）

## 2. 機能一覧
| # | 機能名 | 説明 | 優先度 |
|---|--------|------|--------|
| 1 | ...    | ...  | 必須/任意 |

## 3. 画面設計
### 画面一覧
- {画面名}：{役割}

### 各画面の構成要素
#### {画面名}
- ヘッダー：
- メインコンテンツ：
- フッター：
- 操作ボタン・入力フォーム：

## 4. データ構造
### ローカルストレージ
```json
{
  "key": "型と説明"
}
```

### 状態管理（JS内変数）
- `変数名`：型・用途

## 5. 操作フロー
1. ユーザーが〜する
2. システムが〜する
3. 〜が表示される

## 6. デザイン方針
- カラースキーム：
- フォント：
- レイアウト：
- レスポンシブ対応：有/無

## 7. 技術仕様
- 実装形式：HTML/CSS/JS 単一ファイル
- 外部ライブラリ：{使用する場合はCDN URLも記載}
- ブラウザ対応：Chrome/Firefox/Safari 最新版
- GitHub Pages対応：index.htmlとして出力

## 8. 制約・除外事項
- {スコープ外の機能や制限事項}
```

---

## Phase 3: 仕様レビュー・修正

仕様書提示後、以下を明示する：

```
この仕様書で進めてよろしいですか？
修正したい箇所があれば教えてください。
合意後に実装を開始します。
```

ユーザーから修正依頼があれば仕様書を更新して再提示。**「OK」「進めて」などの合意が取れるまで実装しない。**

---

## Phase 4: 実装

### 実装ルール

1. **単一HTMLファイル**で完結させる（`index.html`）
2. CSS は `<style>` タグ内に記述
3. JS は `<script>` タグ内に記述（末尾推奨）
4. 外部リソースはCDNのみ使用（ローカルファイル参照禁止）
5. GitHub Pages前提のため、サーバーサイド処理は使用しない
6. `localStorage` でデータ永続化（必要な場合）

### デザインデフォルト値（指定がない場合）

```css
/* カラースキーム */
--color-bg: #f8f9fa;
--color-surface: #ffffff;
--color-primary: #3b82f6;
--color-text: #1f2937;
--color-muted: #6b7280;
--color-border: #e5e7eb;

/* タイポグラフィ */
font-family: 'Segoe UI', system-ui, sans-serif;
```

### GitHub Pages対応チェックリスト

- [ ] ファイル名が `index.html`
- [ ] 相対パスのみ使用（絶対パス禁止）
- [ ] 外部リソースはHTTPS CDNのみ
- [ ] `<meta charset="UTF-8">` 記載あり
- [ ] `<meta name="viewport" ...>` 記載あり（レスポンシブ対応時）

### 実装完了後

ファイルを `/mnt/user-data/outputs/index.html` に保存し、`present_files` で提示する。

---

## Phase 5: 再生成プロンプト出力

実装ファイルの末尾（HTMLコメントブロック）に再生成プロンプトを埋め込む。

```html
<!--
==================================================
再生成プロンプト
==================================================
以下のプロンプトをClaudeに送ることで、このアプリと同等のものを再生成できます。

【プロンプト】
{アプリ名}をHTML/CSS/JS単一ファイルで作成してください。GitHub Pages公開を前提とします。

## 機能要件
{機能一覧を箇条書きで}

## 画面構成
{画面一覧と各画面の構成要素}

## データ構造
{localStorageのキーと型}

## デザイン
- カラースキーム：{primary, bg, surface, text}
- レイアウト：{レイアウト概要}
- レスポンシブ：{有/無}

## 技術要件
- 外部ライブラリ：{ライブラリ名とCDN URL}
- 単一ファイル（index.html）として出力すること
==================================================
-->
```

---

## ⚠️ 重要ルール

- **仕様合意なしに実装を開始しない**
- **仕様書の項目を省略しない**（わからない場合は「未定」と記載して確認）
- **スコープ外の機能を勝手に追加しない**
- **再生成プロンプトの埋め込みを忘れない**
- ユーザーが「とりあえず作って」と言っても、最低限の仕様確認（目的・主な機能）は行う
