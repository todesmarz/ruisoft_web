# スキルクリエータ 業務フロースキル

このスキルは **新しいAgent Skill（SKILL.md）を設計・実装する手順を定義** する。
「何をスキル化すべきか」「フローをどう分割するか」の価値判断基準は `skill-creator` エージェントの職種定義を参照すること。

---

## 🔄 全体フロー

```
Phase 1: スキル化要件の把握
    ↓
Phase 2: 既存スキルとの重複確認
    ↓
Phase 3: スキル設計（名前・目的・フロー・出力形式）
    ↓
Phase 4: SKILL.md 実装
    ↓
Phase 5: エージェント職種定義の作成（必要な場合）
    ↓
Phase 6: AGENTS.md 更新
    ↓
Phase 7: 検証（セルフレビュー）
```

---

## Phase 1: スキル化要件の把握

ユーザーからスキル化したい業務・作業を聞き出す。以下を明確にする。

- **目的**：何を自動化・標準化したいか
- **入力**：どのような入力から始まるか（依頼文・ファイル・データ等）
- **出力**：最終的に何を成果物として出すか（ドキュメント・コード・リスト等）
- **トリガー**：どのようなリクエストで起動すべきか（キーワード・フレーズ）
- **想定ユーザー**：誰が・どんな場面で使うか

不明点は質問して埋める。曖昧なまま進めない。

---

## Phase 2: 既存スキルとの重複確認

`.claude/skills/` 配下の既存スキル一覧を確認し、新規スキルが既存スキルと重複しないか検証する。

- 完全新規 → そのまま Phase 3 へ
- 既存スキルの拡張 → 既存スキルの SKILL.md を編集する方針を提案
- 既存スキルと一部重複 → スコープ境界を明確に分割し、両者の担当領域を SKILL.md に明記

---

## Phase 3: スキル設計

以下を決定する。

### 3.1 命名
- `kebab-case` で命名（例: `skill-creator`, `seo-audit`）
- 動詞または役割を表す名詞にする
- 既存スキル名と衝突しないことを確認

### 3.2 description（YAML frontmatter）
- 1段落目：スキルの概要（何を・どうするか）
- 2段落目以降：「以下のようなリクエストで必ず使用すること：」+ トリガーフレーズの箇条書き
- 最後：価値判断の参照先エージェントを明記

### 3.3 業務フロー
- Phase分割（ふさわしくは5〜7Phase）
- 各Phaseに「目的」「入力」「手順」「出力」を明記
- 標準手法・フレームワークがある場合は表で明示
- Mermaid等でフロー図を冒頭に配置

### 3.4 出力形式
- 成果物のフォーマット・保存先・ファイル名規約を明記

---

## Phase 4: SKILL.md 実装

`.claude/skills/<skill-name>/SKILL.md` を作成する。以下の構造に従う。

```markdown
---
name: <skill-name>
description: |
  <スキルの概要>
  以下のようなリクエストで必ず使用すること：
  - <トリガーフレーズ1>
  - <トリガーフレーズ2>
  ...
  <トリガーキーワード>のいずれかが含まれる依頼では必ずこのスキルを使うこと。
  価値判断（<判断項目>）は <skill-name> エージェントの職種定義に従うこと。
---

# <スキル名> 業務フロースキル

このスキルは <何を定義するか> を定義する。
<何を判断するか> は `<skill-name>` エージェントの職種定義を参照すること。

---

## 🔄 全体フロー

\`\`\`
Phase 1: ...
    ↓
Phase 2: ...
\`\`\`

---

## Phase 1: ...

...
```

---

## Phase 5: エージェント職種定義の作成

スキルが単独で判断を伴う場合、`.claude/agents/<skill-name>.md` を作成する。

```markdown
---
name: <skill-name>
description: |
  <エージェントの役割>
  実行には <skill-name> スキルを使用する。
  使用例：「<skill-name>エージェントに〜させて」
tools:
  - Read
  - Write
  - Edit
  - Grep
---

# <スキル名>エージェント

## 職種定義

**肩書き：** ...
**一言で言うと：** ...

---

## 哲学
...
```

判断を伴わない純粋な実行スキルの場合はエージェント定義を省略し、SKILL.md内で完結させる。

---

## Phase 6: AGENTS.md 更新

`AGENTS.md` の以下を更新する。

- スキル一覧テーブル（該当カテゴリの行に追加）
- エージェント一覧テーブル（エージェントを作成した場合）
- 開発ライフサイクルマップ（Mermaid図に追加）
- 使用例（該当スキルの使用例を行追加）

---

## Phase 7: 検証（セルフレビュー）

作成したスキルを `self-review` スキルの6観点で検証する。

1. **不整合**：フロー内に矛盾がないか
2. **誤字**：YAML frontmatterの構文・Markdown記法に誤りがないか
3. **わかりやすさ**：初学者でもフローを追えるか
4. **ファクトチェック**：参照する標準手法・フレームワークの由来が正しいか
5. **より良い方法**：既存スキルとの統合可能性はないか
6. **目的達成性**：トリガーフレーズで確実に起動できるか

問題があれば是正する。

- [ ] 業務フローがPhase分割されている
- [ ] （必要なら）`.claude/agents/<skill-name>.md` が作成された
- [ ] `AGENTS.md` のスキル一覧・使用例が更新された
- [ ] セルフレビューを通過した

---

## ⚠️ 注意事項

- 外部リポジトリのスキルをそのままコピーしない（著作権侵害）。概念を参考に独自実装する
- 既存スキルとの重複を必ず確認し、スコープ境界を明確にする
- スキル名は既存スキルと衝突しない `kebab-case` にする
- YAML frontmatterの構文エラーはスキル起動不能に繋がるため必ず検証する
