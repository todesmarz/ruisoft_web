# フロントエンドデザイン 業務フロースキル

このスキルは **フロントエンドUIの視覚的・体験的品質を設計・評価する手順を定義** する。
「何を良いデザインとするか」「トレードオフをどう判断するか」の価値判断基準は `frontend-design` エージェントの職種定義を参照すること。

---

## 🔄 全体フロー

```
Phase 1: デザイン要件の把握
    ↓
Phase 2: デザインコンセプトの策定
    ↓
Phase 3: デザインシステムの設計（配色・タイポグラフィ・スペーシング）
    ↓
Phase 4: レイアウト・コンポーネント設計
    ↓
Phase 5: インタラクション・アニメーション設計
    ↓
Phase 6: 実装（CSS/HTML/JS）とレビュー
    ↓
Phase 7: デザイン品質の検証
```

| 手法 | 由来 | 適用 Phase | 役割 |

| **Material Design** | Google | Phase 2-4 | 標準的なUIデザイン言語の参照 |
| **Human Interface Guidelines** | Apple | Phase 2-4 | iOS/macOS向けデザイン原則 |
| **Fluent Design** | Microsoft | Phase 2-4 | Windows向けデザインシステム |
| **Atomic Design** | Brad Frost | Phase 4 | コンポーネント設計の段階的分割 |

## Phase 1: デザイン要件の把握

以下を明確にする。不明点は質問する。

- **対象プロダクト**：何のUIか（Webアプリ・LP・管理画面等）
- **想定ユーザー**：誰が使うか（年齢・属性・デバイス）
- **ブランド・トーン**：信頼感・親しみやすさ・先進性等の雰囲気
- **参考サイト**：イメージが近いサイト（あれば）
- **制約**：フレームワーク（Bootstrap/Tailwind等）・ブラウザ対応範囲

---

## Phase 2: デザインコンセプトの策定

要件から **3語程度のコンセプト** を定義する。

例：「信頼感・落ち着き・機能的」「親しみやすさ・躍動感・モダン」

コンセプトに基づき、以下を方向付けする。

- **カラーパレットの方向性**（暖色/寒色・彩度の高低）
- **タイポグラフィの方向性**（セリフ/サンセリフ・行間の広さ）
- **余白の方向性**（タイト/エアリー）

---

## Phase 3: デザインシステムの設計

### 3.1 配色（60-30-10法則）
- **主色（60%）**：背景・ベース面
- **副色（30%）**：セカンダリ面・カード・ナビゲーション
- **アクセント（10%）**：CTAボタン・重要要素
- **コントラスト比**：WCAG 2.1 AA基準（通常テキスト4.5:1以上、大テキスト3:1以上）

### 3.2 タイポグラフィ
- **フォント階層**：見出し（H1-H6）・本文・キャプションのサイズ比率（1.250 Major Third等のモジュラースケール）
- **行間**：本文1.5〜1.75、見出し1.1〜1.3
- **字間**：大見出しは詰め、本文は標準

### 3.3 スペーシング（8ptグリッド）
- 基本単位8px（4px補助単位も可）
- 全要素のmargin/paddingを8の倍数に揃える

### 3.4 シャドウ・角丸
- 角丸：4px（小）/ 8px（中）/ 16px（大）の3段階
- シャドウ：3段階（subtle/medium/strong）

---

## Phase 4: レイアウト・コンポーネント設計

### 4.1 レイアウト
- **グリッド**：12カラム or CSS Grid
- **ブレイクポイント**：モバイル（<768px）/ タブレット（768-1024px）/ デスクトップ（>1024px）
- **コンテナ最大幅**：1280px程度（LPは狭め、管理画面は広め）

### 4.2 コンポーネント（Atomic Design）
- **Atoms**：ボタン・入力・ラベル・アイコン
- **Molecules**：検索ボックス・カード・リストアイテム
- **Organisms**：ヘッダー・サイドバー・フォーム群
- **Templates**：ページ枠組み

### 4.3 操作性の法則
- **Fittsの法則**：重要ボタンは大きく、マウス移動距離を短く
- **Hickの法則**：選択肢は7±2以内に抑える
- **Zパターン/Fパターン**：視線誘導に合わせたレイアウト

---

## Phase 5: インタラクション・アニメーション設計

### 5.1 アニメーション原則（Disney 12原則より抜粋）
- **イージング**：linearは避け、ease-out/ease-in-outを使う
- **所要時間**：マイクロインタラクション200-300ms、画面遷移300-500ms
- **控えめさ**：装飾目的のアニメーションは避ける。フィードバック・誘導目的に限る

### 5.2 インタラクション
- **ホバー**：色変化・スケール（1.02-1.05倍）・シャドウ変化
- **フォーカス**：アウトライン（2px solid）で明示
- **ローディング**：スケルトン・スピナー・プログレスバー
- **エラー**：赤色・アイコン・メッセージの3点セット

---

## Phase 6: 実装とレビュー

### 6.1 実装
- CSS変数（カスタムプロパティ）でデザインシステムを定義
- レスポンシブはモバイルファースト
- アクセシビリティ：`aria-*`・`alt`・`role`を適切に付与

### 6.2 レビュー観点
- デザインシステムから逸脱していないか
- レスポンシブで崩れがないか
- アクセシビリティ基準を満たすか
- パフォーマンス（画像最適化・不要なアニメーション）に問題ないか

---

## Phase 7: デザイン品質の検証

以下の観点で検証する。

| 観点 | 確認内容 |
|------|----------|
| 一貫性 | デザインシステムが全体で適用されているか |
| 階層性 | 情報の重要度が視覚的に表現されているか |
| 余白 | 詰まりすぎ・空きすぎがないか |
| コントラスト | WCAG AA基準を満たすか |
| レスポンシブ | 主要ブレイクポイントで崩れがないか |
| アクセシビリティ | キーボード操作・スクリーンリーダー対応 |
| AI感の排除 | テンプレート感・機械的な配色になっていないか |

## 📋 出力チェックリスト

- [ ] デザインコンセプト（3語）が定義された
- [ ] 配色（60-30-10）・タイポグラフィ・スペーシングが設計された
- [ ] コンポーネントがAtomic Designで分割された
- [ ] インタラクション・アニメーションが控えめに設計された
- [ ] WCAG 2.1 AA基準のコントラスト比を満たす
- [ ] レスポンシブ（モバイル/タブレット/デスクトップ）で崩れない
- [ ] 「いかにもAIが作った感」が排除されている

---

## ⚠️ 注意事項

- 装飾過多にならないこと。機能性・操作性を優先する
- トレンド追いかけすぎない。5年後も違和感のないデザインを目指す
- アクセシビリティは後付けせず、Phase 3から組み込む
- ダークモード対応が必要な場合はPhase 3で両パレットを設計する
