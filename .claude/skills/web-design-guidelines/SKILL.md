# Webデザインガイドライン監査 業務フロースキル

このスキルは **Webサイトの品質を6カテゴリ100+ルールで監査し、改善案を生成する手順を定義** する。
「何を問題とするか」「修正優先度をどう付けるか」の価値判断基準は `web-design-guidelines` エージェントの職種定義を参照すること。

---

## 🔄 全体フロー

```
Phase 1: 監査対象の把握
    ↓
Phase 2: 自動チェック実行（可能な場合）
    ↓
Phase 3: 6カテゴリ監査（100+ルール）
    ↓
Phase 4: 問題点の統合と優先度付け
    ↓
Phase 5: 改善案レポート生成
    ↓
Phase 6: （必要なら）修正実装
```

---

## 適用する標準・フレームワーク

| 標準 | 由来 | 適用 Phase | 役割 |
|---|---|---|---|
| **WCAG 2.1** | W3C | Phase 3 | アクセシビリティ基準（A/AA/AAA） |
| **Lighthouse** | Google | Phase 2 | パフォーマンス・アクセシビリティ・SEO・PWAの自動計測 |
| **Core Web Vitals** | Google | Phase 3 | LCP/FID/CLSの3指標 |
| **Nielsen 10原則** | Jakob Nielsen | Phase 3 | ユーザビリティ評価 |
| **OWASP Top 10** | OWASP | Phase 3 | Webセキュリティ基準 |
| **Browser Compatibility** | Can I Use | Phase 3 | ブラウザ互換性確認 |
| **SEO Starter Guide** | Google | Phase 3 | SEO基礎 |

---

## Phase 1: 監査対象の把握

以下を明確にする。

- **対象URL/ファイル**：監査するWebサイト・HTMLファイル
- **対象デバイス**：モバイル/デスクトップ/両方
- **対象ブラウザ**：Chrome/Firefox/Safari/Edge等
- **監査カテゴリ**：全カテゴリ or 特定カテゴリに絞るか
- **深度**：トップページのみ or 全ページ巡回

---

## Phase 2: 自動チェック実行（可能な場合）

ローカルファイル・URLにアクセス可能な場合、以下を活用。

- **Lighthouse**（Chrome DevTools / CLI）：パフォーマンス・アクセシビリティ・SEO・PWAのスコア
- **axe-core**：アクセシビリティの自動検出
- **W3C Validator**：HTML/CSSの構文検証

自動計測が不可能な場合は手動監査（Phase 3）で代替する。

## Phase 3: 6カテゴリ監査（100+ルール）

### 3.1 アクセシビリティ（WCAG 2.1 AA基準・約25ルール）

#### 知覚可能
- [ ] 画像に `alt` 属性があるか（装飾画像は `alt=""`）
- [ ] フォーム入力に `label` が紐付いているか
- [ ] 色だけで情報を伝えていないか
- [ ] コントラスト比が4.5:1（通常）/ 3:1（大テキスト）以上か

#### 操作可能
- [ ] 全機能がキーボードで操作可能か
- [ ] フォーカスが可視化されているか
- [ ] タブ順序が論理的か
- [ ] スキップリンクがあるか（大規模サイト）
- [ ] タイムアウト・自動更新が制御可能か

#### 理解可能
- [ ] `lang` 属性が設定されているか
- [ ] フォームのエラーが明確に提示されるか
- [ ] 入力候補（`autocomplete`）が適切に設定されているか
- [ ] ページタイトルが説明的か

#### 堅牢
- [ ] HTMLが妥当な構造か（W3C Validator）
- [ ] ARIAロール・プロパティが適切に使われているか
- [ ] スクリーンリーダーで情報が正しく読み上げられるか

### 3.2 UX（Nielsen 10原則ベース・約20ルール）

- [ ] システム状態が可視化されているか（ローディング・進捗）
- [ ] 現実世界と一致するメタファーか
- [ ] ユーザーのコントロール・自由度があるか（戻る・取消）
- [ ] 一貫性があるか（同機能は同見た目）
- [ ] エラーを防ぐ設計か（確認・取消・制約）
- [ ] 認知負荷を減らすか（認識>記憶）
- [ ] 柔軟性・効率性か（ショートカット・カスタマイズ）
- [ ] 美しく最小なデザインか
- [ ] エラーメッセージが分かりやすいか
- [ ] ヘルプ・ドキュメントがあるか
- [ ] レスポンシブ対応（モバイル/タブレット/デスクトップ）
- [ ] タッチターゲットが44x44px以上（モバイル）
- [ ] 重要CTAがファーストビューにあるか
- [ ] フォーム項目数が最小化されているか

### 3.3 パフォーマンス（Core Web Vitals + α・約20ルール）

#### Core Web Vitals
- [ ] **LCP**（Largest Contentful Paint）< 2.5秒
- [ ] **FID**（First Input Delay）< 100ms
- [ ] **CLS**（Cumulative Layout Shift）< 0.1

#### 読み込み速度
- [ ] 画像が最適化されているか（WebP/AVIF・遅延読み込み）
- [ ] CSS/JSが縮小・結合されているか
- [ ] 不要なレンダーブロックリソースがないか
- [ ] フォントの読み込みが最適化されているか（`font-display: swap`）
- [ ] HTTP/2・HTTP/3が有効か
- [ ] CDNが使われているか
- [ ] gzip/brotli圧縮が有効か
- [ ] キャッシュヘッダが適切か

#### 実行時性能
- [ ] DOMサイズが大きすぎないか（<1500要素目安）
- [ ] 再描画・再レイアウトが最小化されているか
- [ ] メモリリークがないか
- [ ] アニメーションがGPUアクセラレーション対応か（transform/opacity）

### 3.4 SEO基礎（Google SEO Starter Guideベース・事前スクリーニング約8ルール）

※本カテゴリは seo-audit スキルの軽量スクリーニングです。深いSEO監査（インデックス状況・コンテンツ品質・E-E-A-T・被リンク・ローカルSEO）は seo-audit スキルを使用してください。

- [ ] `<title>` が30文字以内・説明的か
- [ ] `meta description` が120文字以内・要約的か
- [ ] 見出し構造（H1-H6）が論理的か（H1は1つ）
- [ ] URLが簡潔・説明的か
- [ ] OGP（`og:*`）が設定されているか
- [ ] カノニカル（`rel="canonical"`）が適切か
- [ ] モバイルフレンドリーか
- [ ] HTTPS化されているか

※サイトマップ（`sitemap.xml`）・`robots.txt`・構造化データ（Schema.org）・内部リンク構造・ページ速度の詳細監査は seo-audit スキルに委譲。

### 3.5 セキュリティ（OWASP Top 10ベース・約15ルール）

- [ ] HTTPS化されているか
- [ ] HSTSヘッダが有効か
- [ ] CSP（Content-Security-Policy）が設定されているか
- [ ] X-Frame-Options（`DENY`/`SAMEORIGIN`）があるか
- [ ] X-Content-Type-Options: nosniff があるか
- [ ] Referrer-Policyが適切か
- [ ] 入力値検証（XSS対策）がされているか
- [ ] CSRFトークンが使われているか（フォーム）
- [ ] 外部リンクに `rel="noopener noreferrer"` があるか
- [ ] 機密情報がソース・コメントに漏れていないか
- [ ] 依存ライブラリに既知脆弱性がないか

### 3.6 互換性（約10ルール）

- [ ] 主要ブラウザ（Chrome/Firefox/Safari/Edge）で動作するか
- [ ] レガシーブラウザ（IE11等）の対応範囲が明確か
- [ ] `Can I Use` で機能互換性を確認したか
- [ ] ポリフィルが必要な機能に付与されているか
- [ ] プログレッシブエンハンスメントか
- [ ] 印刷用CSS（`@media print`）があるか

## Phase 4: 問題点の統合と優先度付け

検出した問題を以下の優先度で分類する。

| 優先度 | 定義 | 対応目安 |
|--------|------|----------|
| **P0（Critical）** | アクセシビリティ法違反・セキュリティ脆弱性・機能不全 | 即時修正 |
| **P1（High）** | UX阻害・パフォーマンス基準未達・SEO重大問題 | 1週間以内 |
| **P2（Medium）** | 軽微なUX問題・最適化余地・SEO改善余地 | 1ヶ月以内 |
| **P3（Low）** | 美的改善・コード品質・将来対応 | 機会改修 |

## Phase 6: 修正実装（必要な場合）

ユーザーが修正実装も依頼した場合、優先度順に修正する。

- P0から順に対応
- 各修正後に再監査で回帰確認
- 修正内容をコミット単位でまとめる

---

## 📋 出力チェックリスト

- [ ] 6カテゴリ100+ルールを全て確認した
- [ ] 問題点に優先度（P0-P3）が付与された
- [ ] 各問題に根拠（WCAG/Nielsen/OWASP等）が明記された
- [ ] 改善案に具体的コード例が含まれる
- [ ] 改善ロードマップが提示された

---

## ⚠️ 注意事項

- 自動チェックだけでなく手動監査を必ず併用する（自動検出限界がある）
- アクセシビリティは法的リスク（P0）になり得るため最優先
- パフォーマンス指標は実環境計測を重視する（開発環境のみでは不正確）
- 監査レポートは対象者（開発者/非エンジニアPM）に合わせて表現を調整する
